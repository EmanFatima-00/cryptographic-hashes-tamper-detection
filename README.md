# File Integrity Checker

A command-line tool that computes **SHA-256** hashes for all files in a folder, saves them in a baseline manifest and later reports which files were **modified, new or missing**. Built for the CodeNova Cyber Security Internship (Task 3).

## Features

- SHA-256 hashing of every file, including nested sub-folders
- Structured JSON manifest: relative path, hash, size and modified time (UTC)
- Verify mode with separate **MODIFIED / NEW / MISSING** sections
- Detects tampering by content hash, so a change is caught even when **file size and timestamp look identical**
- Manifest digest, so edits to the manifest itself are flagged
- Files are read in 64 KB chunks, so large files are fine
- Permission or I/O errors are listed as *unreadable* and do not crash the tool
- Exit codes: `0` intact, `1` changes found, `2` error

## Requirements

- Python 3.8 or newer
- No external packages (standard library: `hashlib`, `os`, `json`, `argparse`)

## Usage

```
python task3.py baseline <folder> [-m manifest.json]
python task3.py verify   <folder> [-m manifest.json]
python task3.py demo
```

Example:

```
python task3.py baseline C:\test_folder -m manifest.json
python task3.py verify   C:\test_folder -m manifest.json
```

The manifest file is excluded from its own scan. Symbolic links are skipped.

## Manifest format

```json
{
  "version": 1,
  "algorithm": "sha256",
  "created_utc": "...",
  "root": "absolute path of the folder",
  "file_count": 5,
  "files": {
    "docs/policy.txt": {
      "sha256": "...",
      "size": 51,
      "modified_utc": "...",
      "mtime_ns": 0
    }
  },
  "manifest_digest": "..."
}
```

Keep the manifest somewhere an attacker cannot also edit (for example a separate or read-only location). A manifest stored next to the files it protects offers weaker assurance.

## Tamper simulation

`python task3.py demo` creates a `demo_folder` with nested sub-folders and then:

1. Creates a baseline.
2. Verifies the untouched folder.
3. Flips a **single byte** in `docs/policy.txt` and restores its original size and modified time.
4. Adds `docs/new_file.txt` and deletes `bin/tool.bin`.
5. Verifies again.

## Limitations

- Detects changes; it cannot tell *who* made them or whether they were authorised.
- The tool is only as trustworthy as the baseline: create it while the folder is known to be clean.
- It is a point-in-time check, not a real-time monitor.
